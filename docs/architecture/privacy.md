# Хранение и данные пользователя

## Первая версия

Без обязательного аккаунта и без сервера для локальных функций. SwiftData хранит профиль, историю веса, график, планы и результаты. UserDefaults допустим для темы и других несекретных настроек. API-ключи — только Keychain, с политикой доступа для разблокированного устройства и без переноса на другие устройства. Конкретные параметры адаптера закрепляются в спринте интеграции.

Не включаем вес, ограничения, ключи и содержимое разговоров в диагностические логи. Для диагностики достаточно типа операции, обезличенного requestID и кода ошибки. Не подключаем стороннюю поведенческую аналитику в первый прототип.

## Контроль пользователя

- Параметры и цель редактируются; смена цели применяется к новым планам.
- Облачная отправка имеет отдельное включение и понятное описание состава данных.
- Историю общения можно удалить отдельно от тренировок.
- «Удалить все данные» требует подтверждения и очищает БД, черновики, локальный ключ, кэш, ожидающие и доставленные уведомления приложения.
- Удаление приложения не считаем гарантией удаления Keychain; сценарий очистки ключа реализуется явно.
- Экспорт истории в переносимый файл — перед публичным релизом; для прототипа документируем отсутствие этой функции.
- До появления собственного backup/sync предупреждаем в настройках, что восстановление истории между устройствами не реализовано. Отдельно определить политику системных резервных копий при создании persistence-слоя.

Локальная очистка не обещает удаление уже переданных данных у внешнего поставщика. Для облачного режима отдельно описываем хранение, удаление и сроки на backend и стороне провайдера до его подключения.

## Реализованный срез (1 октября 2026)

Проверено автотестами хранилища и сквозным сценарием «удалить всё» на подменном хранилище и планировщике. Не проверено: ручной проход экрана «Данные» в симуляторе, поведение на устройстве, системные резервные копии.

- **Данные только на устройстве.** Сетевого кода в приложении нет, сторонней аналитики нет, `UserDefaults` и Keychain не используются, API-ключей нет. Всё хранится в SwiftData (см. [модель данных](data-model.md)).
- **Экспорт.** «Профиль → Данные → Экспортировать» собирает один JSON-файл (профиль, тренировки по подходам, вес, расписание, достижения, настройки) и отдаёт его системному окну «Поделиться». Файл создаётся во временной папке приложения с защитой `completeFileProtection`; дальше он уходит туда, куда человек его отправит. Импорта пока нет, поэтому файл — копия на случай смены устройства, а не перенос.
- **Удаление.** «Удалить все данные» требует подтверждения и очищает все документы хранилища (профиль, черновик, журнал, расписание, вес, настройки, достижения, снимок тренировки), снимает запланированные и показанные уведомления приложения и возвращает приложение к первому запуску. Если запись не удалась, ничего не меняется, и показывается сообщение. Системные резервные копии устройства не затрагиваются; об этом нужно сказать в описании для магазина.
- **Уведомления.** Разрешение запрашивается только при включении напоминаний. Тексты не содержат вес, цель и ограничения.
- **Манифест приватности.** `Resources/PrivacyInfo.xcprivacy`: отслеживания нет (`NSPrivacyTracking` = false), собираемые типы данных, домены и обращения к API с обязательной причиной — пусты. Это соответствует коду на дату записи (нет `UserDefaults` и других API из списка Apple); при добавлении таких обращений манифест надо пересмотреть. Заполнение сведений App Store и политика приватности остаются на подготовку релиза.
- **Журналы.** Единственный системный лог (`Logger`, категория notifications) пишет только код ошибки уведомлений, без пользовательских данных. Вывода через `print` нет.

## Подготовка публичного релиза

Зафиксировать фактические потоки данных, политику приватности и описания разрешений, заполнить сведения App Store на основе реализованного поведения. Не запрашивать HealthKit, контакты или геолокацию без соответствующей функции. Уведомления — только по выбранному пользователем действию.

Это технический план продукта, а не заключение о соответствии законодательству или правилам магазина. Проверка актуальных требований входит в подготовку релиза.

## После MVP: доступ живого тренера

Связь с тренером открывает только явно согласованную область данных. Перед принятием приглашения клиент видит, какие параметры и результаты будут доступны. Прошлая личная история, AI-переписка и ключи по умолчанию закрыты. Доступ ограничивается на сервере, а не только интерфейсом.

Завершение связи и удаление аккаунта — разные операции. При завершении связи клиент сохраняет свои результаты и полученные snapshots, тренер теряет доступ к данным клиента. Перед реализацией удаления аккаунта определяем удаление серверных копий, вложений и кэшей, а также судьбу авторских шаблонов и уже полученных клиентами заданий; не распространяем локальную кнопку удаления MVP на облачные данные без отдельного сценария.
