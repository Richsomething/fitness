# AI и подключаемые провайдеры

## Решение

Основная функциональность работает без AI. «Готовый режим» для пользователя означает отсутствие необходимости приносить ключ: сначала это локальные сценарии и моки, позднее — собственный алгоритм и, при необходимости, управляемый облачный AI для общения. Не называем мок настоящей моделью.

| Режим | Назначение | Зависимости |
| --- | --- | --- |
| Local / Mock | Реплики персонажа и демонстрационный план | Только устройство |
| Managed AI | Разговоры и объяснения через сервис приложения | Интернет, backend, лимиты расходов |
| Claude BYOK | Пользователь подключает свой API-ключ | Интернет, ключ, доступ пользователя к API |

Приоритет: Local → Managed AI → опциональный BYOK. BYOK не нужен для онбординга и не блокирует первый релиз. Название и версия облачной модели задаются конфигурацией, а не UI и бизнес-правилами.

## Две разные ответственности

**PlanGenerator** строит формальный кандидат плана. Сначала MockPlanGenerator, в последней итерации RuleBasedPlanGenerator по материалам тренера. **CoachService** формулирует поддержку и объяснения. Смена аватара меняет общение, но не правила нагрузки.

В будущем AI может предложить кандидата через отдельный AssistedPlanGenerator. Кандидат проходит ту же валидацию по каталогу, расписанию и правилам тренера. Невалидный ответ не становится тренировкой. Обычный чат не имеет права записывать новые занятия или переносить существующие без отдельного пользовательского действия.

## Облачная граница

Предлагаемый поток Managed: iPhone → наш API → поставщик AI. Ключ приложения хранится на сервере. Backend проверяет доступ, ограничивает расходы и частоту, валидирует запрос, задаёт таймаут и возвращает нормализованный ответ. Технологию backend выбираем в спринте AI; сервис для раннего прототипа не требуется.

Проектный контракт: POST /v1/coach/messages, requestID, personaID, locale, message, минимальный context, contractVersion. Ответ: messageID, text, origin, requestID. Ошибки: unauthorized, quotaExceeded, rateLimited, unavailable, invalidResponse. Не записываем свободный текст диалога в общие серверные логи.

BYOK: iPhone → Claude API через отдельный адаптер. Ключ хранится в Keychain, не отправляется нашему backend и не попадает в логи. Настройки показывают только факт подключения, кнопку проверки и удаления. Проверка может расходовать API-квоту — это явно указано рядом с действием. Перед реализацией повторно проверяем условия провайдера и доступность для целевой аудитории; не обещаем, что подписка на чат равна API-доступу.

## Поведение и ошибки

- AI подключается явно; до первой отправки показываем, какие данные и кому будут переданы.
- Передаём выбранную цель и контекст занятия только когда нужны. Имя, точный вес и ограничения не включаем автоматически в каждый запрос.
- Без сети доступен сохранённый план и локальные реплики; статус режима видим пользователю.
- При 401 предлагаем заменить ключ; при лимите — повторить позже или использовать локальный режим. Не переключаем платный режим молча.
- Повтор запросов ограничен; отмена доступна. Потоковая выдача — улучшение после обычного запроса.
- Запрос привязан к версии контекста. Поздний ответ не меняет выбранного тренера или уже обновлённый план.
- Содержание импортированных тренировок — данные, а не системные инструкции для AI.

## 100+ тренировок не равны обученной модели

Сначала нормализуем материалы, извлекаем упражнения и правила, проверяем их с владельцем. Базовый путь — детерминированный алгоритм плюс поиск по каталогу для объяснений. Дообучение модели не является обязательным результатом импорта и рассматривается отдельно при доказанной необходимости.

Справочные точки на 28.09.2026: [Claude API overview](https://platform.claude.com/docs/en/api/overview), [аутентификация](https://platform.claude.com/docs/en/manage-claude/authentication). Архитектура режимов выше — наше решение; тарифы и точный набор моделей здесь намеренно не зафиксированы.
